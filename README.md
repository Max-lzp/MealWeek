# MealWeek · 运动与饮食手记

中文、手机优先的个人运动饮食网页 MVP。基于 [Tally](https://github.com/GeneArnold/tally) 固定版本 `58dee54e3ee957e7d360133ce7dbc7c42741db63` 的 Next.js / React / TypeScript 底座二次开发。

**当前 MVP 采用浏览器本地保存，不接 Tally 账户或 SQLite 日记。AI 模型仍在选型，真实图片/文本模型识别尚未完成、未接入任何模型 API；不提供云同步或医疗建议。** MIT 许可证与 Gene Arnold 署名完整保留。原 README 位于 `docs/UPSTREAM_README.md`；需求附件原文位于 `docs/MEALWEEK_SPEC.md`，其中的计划不代表已完成能力。

## 启动

要求 Node.js 24（本环境验证 24.19.0）、npm 11。

```bash
cd /workspace/MealWeek
npm ci
npm run dev -- --hostname 0.0.0.0 --port 3000
```

本机访问 `http://localhost:3000`。手机访问需要与主机互通，用主机局域网 IP 和 3000 端口；云环境的 localhost 不能直接从手机打开，需要产品支持的端口转发或经你确认的 HTTPS 演示托管。本次未创建公网地址或发布服务。文件选择可使用系统拍照入口，是否提供拍照由手机浏览器决定；无独立相机 API。

生产模式（推荐演示时使用）：

```bash
npm run build
npm run start -- --hostname 0.0.0.0 --port 3000
```

MVP 无必填环境变量、模型密钥或数据库迁移要求。上游 SQLite 迁移已单独在 `/workspace/tally-upstream` 验证，不是本地 MVP 启动的前置条件。原生上游路由默认关闭，勿为本轮演示开启 `MEALWEEK_ENABLE_UPSTREAM`。

## 本轮完成

- 今日 / 添加 / 周报 / 我的四个中文页面，底部导航，360 / 390px 视口可用。
- JPG、PNG、WebP 照片本地解码、限大小、缩放到最长边 800px 并重编码 JPEG；不上传服务端或模型。HEIC 明确提示转换。
- 每条食物包含餐次、日期、名称、份量、整份热量上下限、来源、更新时间、可选照片；逐条审核保存，同一餐可继续添加多个条目。
- 食物增删改；保存按草稿 ID 幂等。更改食物后撤销整日完整确认，需再次核对。
- 运动增删改、时长、消耗与来源；全天总消耗单独输入及清除，设备总数不加运动。
- 未知值保留未知，已知小计与部分记录有提示。只有完整饮食且全天消耗已知时计算 `摄入 − 全天总消耗`。
- 七日摄入范围、总消耗、饮食完整状态及逐日明细；缺失日期留空；点击某日返回当天记录。
- 独立演示空间、加载 / 清除演示数据；个人空间不被演示覆盖。
- 手动摄入目标、确认修改、历史版本，自生效日起显示；与目标差额和能量盈亏分开。
- 用户主动确认的偏好增删改、来源、更新时间、可选有效期；过期或删除后停止参与今日 / 周报提示。
- 本地持久化、当前空间 JSON 导出、个人数据清除；写入失败提示且不显示保存成功。

## 模型识别：选型中，尚未完成 / 未接入 API

保留“AI 识别填入”和“人工填写”两个入口。AI 页面明确展示“模型选型中 · 未接入 API”，真实识别按钮不可用；照片只在当前浏览器压缩和保存，不调用 DeepSeek、Gemini 或其他模型接口。本轮根据用户决定暂停 API 接入，不把接口草案或模拟结果写成已接通 AI。

人工填写可以直接输入名称、数量、热量；也可以通过下面的文字 / 语音辅助预填。所有预填结果均需用户审核和确认，不能自动入账。

“模拟识别”保留在表单底部的独立演示折叠区，只有用户主动打开并确认才填入固定鸡肉饭示例，明确标注“演示结果，非真实图片识别”。它不分析上传的照片，不能用于真实识别验收。

## 文字与语音快速填写（不依赖模型 API）

- “添加”中输入“米饭200克，一个鸡蛋”，立即显示内置参考表的粗估；点击“填入待审核表单”会填写名称、份量和热量范围，仍可修改后确认保存。
- 支持的浏览器可点击“语音输入”，说出完整食物描述；选择“追加”可继续加食物，也可说“把米饭改成150克”改写已有数量。语音结果先转成可编辑文字，再用同一确定性规则估算。
- 未匹配食物、缺少数量、不明确的“一碗 / 一份”等不猜测重量；有未知项时仅显示已知小计，填入整餐时热量保持未知，不补零。
- 20种通用参考食物及假设在页面折叠表中公开，按可食部计算，默认不含额外油或酱料。数值是原型参考值，尚未逐项校验为权威营养数据库。范围为参考值上下约20%向外取整，不是测量误差或统计置信区间，不保证覆盖实际热量。**文字估算不是 AI，也不能准确计算任意菜品。**
- 语音使用浏览器 Web Speech API（zh-CN）；可能由浏览器 / 系统将音频发送至其语音服务，本应用不记录或保存音频，也没有接入独立语音 API。点击后才请求麦克风，支持停止、取消、拒绝权限和失败后继续打字。
- 语音需要 HTTPS（localhost 开发环境除外），且浏览器支持。部分手机或微信内置浏览器不可用，系统语音服务也可能受网络影响；此时使用文字框或手机键盘自带语音按钮。
- 已验证的是模拟 SpeechRecognition 事件、权限失败降级和文字流程；**尚未验证真实手机麦克风转录效果**。


## 一分钟演示

1. 添加 → 人工填写 → 输入或说“米饭200克，一个鸡蛋” → 参考估算填入 → 修改并确认保存；照片可选上传。AI入口会明确展示尚未接入。
2. 今日 → 记录篮球 60 分钟、500 kcal → 填设备全天总消耗 2300 kcal → 确认饮食完整；观察总数不变成 2800。
3. 修改 / 删除食物，观察小计更新且完整状态撤销；刷新检查记录保留。
4. 周报看缺失日留空；我的 → 加载七日演示 → 周报查看范围与完整度。
5. 我的 → 添加“不喜欢香菜”并确认 → 今日看提示 → 删除偏好，提示消失；清除演示回个人空间。

## 已知限制与后续

- 没有真实手机硬件测试，验证的是 Chromium 的 360 / 390px 视口；本次输入功能更新的线上版本需以 Netlify 发布记录为准。
- 无账户、云端持久化、跨设备同步、导入、数据库迁移、离线 PWA 保证；浏览器存储非加密保险箱，共用设备可能访问数据，清站点数据会丢失。浏览器额度有限，请定期导出。
- 一次保存一个餐食条目，文字可包含多种食物并合并估算；无照片自动分割、完整营养数据库匹配、营养素或体重趋势。
- 消耗仅支持明确来源的全天总数（点估计）；没有“基线＋净运动”模式或消耗上下限。基线不明时请留空。
- 记忆只做主动声明的偏好；无推断、向量库、自动冲突检测或 Agent。偏好之间有冲突时由用户编辑原条目解决。
- 不自动开热量目标，不预测体重变化，不根据一天数据调整计划。
- 保留的上游路由代码未做完整安全审计，默认由中间层关闭；原食品库、账户、Recharts 图表没有作为本轮 MVP 功能复用。

# 本轮取舍

1. 优先可运行记录流程：保留 Tally 框架，新增一个本地前端入口；账户与 SQLite 日记集成留待后续，避免在一小时窗口改动复杂既有业务链路。
2. 不让 AI 成为前置条件：模型配置不存在，手工录入始终可用。模拟入口需独立操作与确认，来源持续保留。
3. 日期使用浏览器本地日期，历史数据按记录日期归属。目标采用生效日期与创建时间的版本列表，不重写旧日期目标。
4. 份量是描述，热量按整份直接输入上下限，不推断换算。全天设备消耗不叠加运动。完整确认与未知数据决定能否输出差额。
5. 不自动修改目标：用户手动输入并确认，周报只给记录完整度与复盘提示。
6. Memory 和日记分离：仅主动声明偏好；当前有效偏好直接从持久化数据过滤，无模型检索或摘要缓存；删除从当前数据移除偏好值。
7. 演示与个人空间在存储中隔离；同一浏览器内共享整份状态，原生 storage 事件同步其他标签页。没有跨标签页并发事务或冲突合并保证。
8. 不注册上游 service worker、不请求 Google 字体，避免继承不必要的私有数据缓存与外部字体依赖。不是完整离线 PWA。
